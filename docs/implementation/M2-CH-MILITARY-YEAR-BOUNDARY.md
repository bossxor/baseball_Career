# M2-CH — 복무·지급 원장의 연도 경계 수정

2026-10-22. 61a0343 다음 작업. ACTIVE/반년 복귀 연결을 조사하던 중 기존 날짜 비교의 오류를 발견했다. 경기 달력의 worldDay는 매년0부터 다시 시작하는데 CB/CG가 숫자 하나로 순서를 검사하고 있었다.

## 재현과 수정

- 2031년303일에 첫 블록을 마친 뒤2032년150일에 둘째 블록을 마치면 INVALID_SERVICE_BLOCK이 발생했다. 회귀2건의 수정 전 실패를 [증거](evidence/M2-CH-before.log)에 보존했다.
- 복무 완료는 seasonKey+worldDay의 사전식 순서로 비교한다. 다음 연도의 더 작은 날짜는 허용하며 과거 연도·중복 완료일 변경·블록 순서 위반은 거절한다. 완료 날짜/성장/계약액을 소급 재작성하지 않는다.
- 지급도 같은 시즌 날짜 비교를 사용한다. 다음 시즌 날짜가 작아져도 실제 등록1경기를 지급하고, 과거 연도의 영수증 재호출은 추가 지급0원이다. 같은 해 역순·이전 연도 신규 지급은 거절한다.

## 호환과 복구

새 원장은 schemaVersion2와 resume.completedSeasonKey를 쓴다. 기존 v1은 읽기에서 바꾸지 않고 예전 절대 날짜 비교를 유지한다. 같은 원래 복무 프로그램·동결 계약·완료 근거가 있는 resumeKboContractPayments 명령으로만 v2로 확장하며 지급 영수증·원금·지급액은 그대로 보존한다. 추정한 연도를 끼워 넣지 않는다. v2가 복귀 연도를 잃으면 명시적으로 거절한다.

옛 바이너리는 v2를 거절하므로 v2를 v1로 강제 축소하지 않는다. 롤백은 마이그레이션 전 저장 스냅샷과 해당 코드 버전을 함께 복원하는 절차이며, 적용 후 지급분이 있으면 이를 버리지 않고 새 코드에서 검토해야 한다. 현재 실서비스 DB 마이그레이션/계정 세이브는 없고 순수 엔진 상태의 호환 검증이다.
