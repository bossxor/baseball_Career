# M2-EJ 후속 구현 계획 — 미국 계약 원점

2026-10-28. 이 문서는 구현 계획이며 완료 증거가 아니다. EI 전체 검증 동안 소스를 변경하지 않고 기존 연결 계획을 구체화했다. 기준은14/23의 사용자 결정과 M2-POST-EH-IMPLEMENTATION-PLAN.md다.

## 범위와 순서

1. 새 KBO 미국 활성화의 계약 시작 시즌과 선수 나이를 일치시킨다. 새 제안은 계약 시작 시즌 나이로 기간을 산정한다. 이미 봉인된 제안과 저장된 나이는 소급 변경하지 않는다.
2. KBO 출신의 미국 초기 계약·초기 예산 예약 후 inventory·시작 나이를 불변 원점으로 보존한다. 기존 고교 직행의 원점과6시즌 보유는 유지한다. 기존 KBO 첫 시즌 저장은 읽을 수 있어야 하며 과거 재무 근거가 없으면 현재 live 예산에서 과거를 역산하지 않는다.
3. usCareerView·openingUsMinorInventory·openingUsMajorYear·usSalaryEntitlement 및 실제 콜업 작성자가 같은 원점을 읽도록 연결한다. 최초 MLB 계약과 마이너에서 콜업한 계약을 구별한다. 원점 도입만 하고 사용하지 않는 상태로 완료 처리하지 않는다.
4. KBO 출신 마이너의 만료는 서명한 기간을 기준으로 한다. 고교 직행6시즌을 더하지 않는다. 유효 다년계약의 급여·기간·권리와 지급액을 재가격하지 않는다. 종료 이후의 새 마이너 제안은 사용자 확정1년·연$30,000이다. 제안 수·구단 선정 등 실제 미정 항목은 기존 문서를 더 확인한 뒤 질문한다.
5. 미국 종료 후 국내 복귀는 실제 미국 나이·기록·부상·현재 능력치를 보존해야 한다. 옛 KBO snapshot으로 선수를 되돌리지 않는다. 국내 보유권·계약/원화와 미국 달러 원장은 각 소유 경계에서 유지한다.

## 보존과 증거

기존 고교 직행 저장과 첫75경기 고정해시, legacy KBO root 조회, 신규 KBO 미국 진입/JSON 재개, 유효 계약 경계, 콜업 다음 날 일할 급여/예산, 연도 전환 재무 재생, 오래된 revision과 잘못된 원점의 원본 불변을 검사한다. 필드를 추가하면 기존 reader/writer 호환 범위를 명시한다. 과거 원점을 복원할 증거가 없는 저장을 자동으로 고치지 않는다.

통제된 연말 archive fixture와 실제 전체 시즌은 별도 표기한다. 집중 회귀는 수정 전 실패를 확인하고, 묶음이 끝나면 전체 npm run check1회 및 HTTP 스모크를 실행한다. 실행 중 소스를 고정한다. 증거·STATUS·PROGRESS·NEXT·HANDOFF 갱신 후 own branch 커밋/푸시, V 문서 Copy-Item만 수행한다.

## EJ 연결 상태 (검증 완료)

EJ는 새 원점/시작 나이·제안 나이·두 종류 MLB 원점의 연간 재생·첫 콜업 급여·서명 기간 경계까지 구현했다. legacy 원점 없는 저장은 조회만 유지하고 현재 live 예산에서 과거 초기 예산을 추정하지 않는다. 전체 npm run check 종료0: 엔진/API 787개 중785통과·실패0·Neon환경 미설정2건 건너뜀, 웹22/22. lint/타입/build/엔진골든/이벤트/설계10종/Android셸/자산·HTTP 스모크 통과. duration_ms 810442.1035, 동결 대상460파일 변경0. 실제 Neon/브라우저/APK 검증은 아니다. 상세는 M2-EJ-KBO-US-CONTRACT-ORIGIN.md를 따른다.
