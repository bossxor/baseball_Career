# M2-AT — KBO·퓨처스 실제 시즌 일정

2026-10-21. 01의 두 독립 리그·각10구단/팀144·전체720·상대별 홈8/원정8과14의 국제창 barrier를 실제 일정에 연결했다. 기존 순환 대진/홈원정 함수는 변경하지 않았다.

## 동작과 기본값

createKboSeasonSchedules는 calendar-1의 세계2~10월 가용 날짜에144개 라운드를 균등 배치한다. 프로 경기의 구체적 시작/종료일은 별도 지정이 없어 기존 세계 성장창을 사용하는 구현 기본값(D)이다. 실제 KBO 달력을 재현하지 않는다. 국제창을 제외하고 한 팀은 하루1경기 이하, 연속6경기 이하, 동일연도 안에 완료한다. 성장 예산의 W는 기존 전체 growthDays로 유지하며 경기일144로 바꾸지 않는다.

confirmKboSeasonSchedule는 유효한 개막 명단 뒤에만 두 리그 일정을 단일 결과로 확정한다. 일정 영수증·revision 외에는 상태를 바꾸지 않는다. 같은 원본 재실행/JSON 복원/확정 후 중복 요청이 같은 결과다. 조회는 내 실제 등록 리그의144개 fixture와 공개 구단 신원만 제공한다. 미확정 구 저장값은 PENDING이고 조회로 생성하지 않는다. 일정 수정/누락/잘못된 리그/영수증을 자동 복구하지 않고 거절한다.

두 리그의 같은 날짜 대진은 서로 다른 simulationKey를 쓴다. 선수의 실제 중복 출장은 후속 경기 worker가 현재1군/2군 선수단을 서로 배타적으로 투영해 검사해야 한다. 지금 단계에서는 실제 경기를 기록하거나 출장·치료/피로·성장·구종XP·급여를 지급하지 않는다.

## 검증

- 관련39/39(29.44초): 신규4 + 기존 개막/계획/관계·달력/대진 회귀. 2029~2032의 모든 국제창 패턴과2100/2400 윤년 예외·9999 경계, 리그별720/팀144/상대별8·8/홈72,144경기일과 휴식·키1440개 고유성을 확인했다.
- 실제 신인 서명→등록→계획→명단→일정의 JSON/중복·알림ACK 보존·부작용0, 조회 공개 allowlist, 날짜/영수증 변조·버전 거절을 확인했다.
- 타입·lint·전체 build·compiled 골든·이벤트 동기화·설계 정적10종·HTTP smoke 통과. 증거는 evidence/M2-AT-*.log다. 첫 타입 검사에서 테스트의 E08 호출 인자 형태가 틀려 기존 함수 시그니처에 맞춰 수정한 뒤 재검증했다. 전체 장기 시즌 묶음은 이번 단계에서 재실행하지 않았다.

## 호환·후속

competitionSchedule는 optional이며 기존 AS 이전 저장값에 새 일정을 몰래 덧붙이지 않는다. 새 reader를 먼저 배포하고 writer 중지 시에도 확정 일정을 보존한다. DB 원자 저장은 아직 없다. 현재 PRESEASON_SETUP 검증이며 경기 시작 뒤에는 개막/계획 영수증을 역사로 보존하는 별도 진행 검증이 필요하다.
