# M2-CJ — 병역 계약의 실제 구단 예약·지급 연결

2026-10-22. CI 다음 단계. 새 상무 입대부터 opt-in contractPaymentVersion1과 계약의 선택적 servicePay를 연결한다. 기존 일반 계약·초기 세계에 필드를 추가하지 않으며, 예전 복무 저장의 과거 급여를 추정해 환불하거나 영수증을 만들지 않는다.

## 현재 구현과 범위

첫 복무 시즌 활성화 시 동결 계약 원장을 붙이고 원구단 급여 예약을0으로 한다. 둘째 시즌은6월30일 뒤 실제 11팀 퓨처스 일정의 원구단 잔여 경기 수만 미리 예약한다. 미래3년 의무는 지급된 일수와 현재 예약 일수를 뺀 잔여 원금으로 계산한다. 반올림 잔여는 기존 마지막 지급일 규칙을 그대로 따른다.

실제6월30일 복귀 시 동일 프로그램 근거로 원장을 재개한다. 이후 일마감은 원구단 정규 공식 경기와 실제 등록 영수증을 연결해 지급한다. 벤치도 등록됐다면 지급, 상무·포스트시즌·국가대표는 원구단 계약 지급에서 제외한다. 지급할 때 reserved를 줄이고 paid를 늘리며 전체 세계 재무 불변조건을 다시 검사한다. 실패는 기존 진행 명령의 clone 안에서 거절되어 게임/돈의 일부만 게시되지 않는다. 같은 일마감 재호출은 지급0원이다.

잔여 계약은 달력의 연수+1 방식이 아니라 미지급 경기일수로 이월한다. 복무 중 매년 새 E30 재계약을 요구하지 않는다. 내 선수는 원래 보유권을 유지하고 양 리그 정상 편성 보충 계산에서 복무자를 제외한다. 상무 경기에는 계속 참가한다.

## 아직 정하지 않은 경계

잔여 계약이 시즌 중 소진된 뒤의 재계약/자동 연장은 사용자에게 선택을 요청했다. 선택과 후속 구현 전에는 추가 신규 등록 경기의 지급을 CONTRACT_DECISION_REQUIRED로 거절한다. 무료 출전이나 무단 자동 연장으로 처리하지 않는다. 이번 단계에서 계약 만료 뒤 전체 시즌 경로가 완성됐다고 주장하지 않는다.

리그 등록 이동으로 미래 잔여 경기 수가 바뀌면 다음 일마감에 재예약한다. 예산/미래90% 한도를 넘으면 명시 오류로 원자 거절하며 자동 재정 구제를 만들지 않는다. 해당 구제/로스터 선택 UI, NPC 병역 지급, ACTIVE/28세, 병역 성장 계수는 후속이다.

## 호환과 롤백

servicePay 없는 기존 저장은 종전 연봉 계산을 유지한다. 새 opt-in 저장은 동일한 동결 계약키·선수·구단·연봉·원장v2·복귀 날짜를 검증한다. 예전 복무 중 저장은 자동 채택하지 않는다. 실 DB 마이그레이션은 아니다. 옛 코드는 새 예약 합계를 이해하지 못하므로 롤백은 적용 전 저장 스냅샷과 코드의 동시 복원으로 한정한다. 적용 후 지급분을 지우거나 옛 연봉 예약으로 덮어쓰지 않는다.

## 검증

집중14/14 통과 후 잔여연수 표시와 생성 시 복귀 연도 검증을 보강했다. 최종 전체 npm run check 종료코드0·487/487·실패0·취소0·1460384.2591ms 통과. lint·타입·build·골든·이벤트·설계10종도 통과했다. [전체 로그](evidence/M2-CJ-check.log). 실제 복귀 테스트는 이전 기간을 통제된 달력 영수증으로 구성하고 포스트시즌·복귀일 이후 실제 경기를 실행한다. 18개월 모든 경기 검증은 아니다.

전체 구현 추정은35% 완료·65% 남음을 유지한다. 커리어 병역의 작은 슬라이스 추가이며 아직 ACTIVE/미국 실제 리그/전체 사건·화면/DB/구단 조작은 남아 있어 M2 영역50%를 올리지 않았다.

전체 검사 완료 후 진행 문서만 갱신했고 런타임/테스트 해시는 유지했다. 설계 패키지 재생성 뒤 정적10종·해시359개 재검증: [후속 로그](evidence/M2-CJ-post-docs-design.log)·[소스 구분](evidence/M2-CJ-post-docs-source.json).
