# M2-A 선수 육성 기반 인계

2026-10-20. M2의 **부분 완료** 기록입니다. 생성 화면·세계 생성 job·고교 시즌·진로·이벤트99·특성 판정·DB/API는 아직 연결하지 않았습니다.

## 구현 경계

- `packages/rules/src/player.ts`: 고정 버전 글자소 수 계산·NFC 이름 정규화·타자8/투수6 유형의 초기 배열과 상대 성장 weight.
- `packages/engine/src/player.ts`: 검증된 주인공 입력으로18세·6능력·잠재력·최고값 초기화. 이름/손/타석/폼/집중4개 검증. 학교/희망 구단/계정/creationId는 후속 세계 생성 경계에서 검증합니다.
- `development.ts`: 기간별 성장 예산, 정확 정수 배분·상한 재분배, 노쇠, 시즌 중복 정산 차단.
- `training.ts`: 시즌1회 공유, 해금1/3·부상·상한·실제 피로·확정/도전/컨디셔닝/포기, 읽기 전용 미리보기.
- `pitch-xp.ts`: 90의 기본/실제 예산·예약 보호·배율 잔여·구종 상한 손실·근거 중복 차단. 활성구종 구성/숙련 등급/분기 예약 해제·학습 정산은 다음 단계입니다.

현재 함수들은 **서버 내부 계산용**입니다. raw potential/seed를 포함한 결과를 그대로 API에 직렬화하지 않습니다. 학교·구단·소유권·기회·부상·치트 여부·기간별 정책을 클라이언트가 임의로 정할 수 있게 만들지 않습니다. 실제 전이는 확정 세계 상태에서 값을 구성한 뒤 이 함수를 호출해야 합니다.

## 고정 계산

잠재력은42대로 `round(75+10Z)`의 절단정규[-2,2]를 생성해 `[max(A,60),95]`에 제한합니다. Box-Muller2draw/reject 방식이며 normal cache는 없습니다. 같은 주인공 시드에서 일반/하드는 같은 A/P와 RNG cursor입니다. 치트도 같은6개 생성 draw를 소비하고 P만100으로 대체하므로 뒷세계 생성 순서를 임의로 밀지 않습니다. NPC 생성에는 이 함수를 그대로 사용하지 말고85/121의 하드 보너스·손/타석/폼 분포를 별도 적용합니다.

이름 분할은 [unicode-segmenter](https://github.com/cometkim/unicode-segmenter) **0.17.3**을 정확히 고정했습니다. 호스트별 Intl.Segmenter Unicode 데이터 차이에 의존하지 않습니다. UI도 같은 rules의 함수를 사용하고 IME 조합 중 입력을 자르지 않습니다. UTF-8 요청 크기 제한·HTML 텍스트 렌더는 API/UI 단계의 별도 책임입니다.

성장 weight는 상대 정수비입니다. 균형형[1,1,1,1,1,1]은16⅔%씩과 동일하며 이를1%씩으로 표시하지 않습니다. 집중4개는 각각20%, 나머지 합20%입니다. 각 배분은 정수 유리수 half-up 후 합계 차이만 고정 키 순으로 보정하고 상한 잔여를 재분배합니다. G10/거포 예제는2/2/2/2/.6667/1.3333이며 총10을 보존합니다.

기간은 `[startDay,endDay)`이며 겹침을 거절합니다. 나이는 **시즌 시작 snapshot**을 전달하고, 등록 레벨/기간 출장/정규일수와 정책을 고정합니다. 현역 일반 복무는0, 치트/일반 소속 기간은 각각의 배율을 한 번만 적용합니다. 합산 후1e-4단위에 한 번 반올림합니다. 세계 달력·기간별 P snapshot·이적·강화 전후의 실제 정산 순서는 M2 후속 전이에서 연결해야 합니다. 노쇠는 치트 배율을 적용하지 않고 과거 최고값을 유지합니다.

`settleNaturalGrowth`와 `applySeasonTraining`의 완료 시즌 목록은 저장·복원 대상입니다. 같은 API 명령 재시도는 M3 receipt를 먼저 반환해야 하며 새 명령으로 동일 시즌 기회를 재사용할 수 없습니다. 지금의 순수 함수 중복 차단은 DB 행잠금·2기기 경합 검증을 대신하지 않습니다.

XP ledger는 동일 playerSimulationKey/worldSeasonId에 계속 사용합니다. 이적·승강·복무 복귀로 새 ledger를 만들지 않습니다. 근거에는 당시 policyNumerator5/6/15와 후보 기본 지급량을 고정합니다. 동일 근거를 다른 구종/정책/양으로 재사용하면 거절하고,0지급도 처리 완료로 남깁니다. 실제 cap보다 과거 spent가 많아지는 전환은 허용하되 추가 지급은0입니다.
