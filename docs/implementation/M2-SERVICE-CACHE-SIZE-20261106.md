# 서비스 2년 접두 캐시 크기 한계 — 2026-11-06

서비스 2년 후 재계약(`resignUsAfterAmateurReturn`) 검증용 native 접두 캐시가 두 번 같은 지점에서 실패했다.
- 1차(다른 환경, 58분): `RangeError: Invalid string length`, 직전 체크포인트 524,395,902바이트.
- 2차(이 환경, 65분): `source`와 중복되는 service 경기를 뺀 slim 저장으로 재시도했으나 같은 지점(서비스 1년차 약 1,500걸음)에서 동일 실패. 로그: `evidence/M2-20261106-slim-service-run.log`.

해석: 중복 제거로는 줄지 않는다. 서비스 1년(8,790경기)의 리그 전체 경기 기록 자체가 JSON 약 512MB(JS 문자열 한도)를 넘는 규모로 자란다. 단일 문자열 캐시/직렬화로는 2년을 담을 수 없다. 이는 테스트 캐시 문제만이 아니라, 군 복무 중 리그 전체 경기 기록을 저장 문서에 모두 두는 현재 구조의 크기 위험(PostgreSQL jsonb 한도 포함)을 시사한다. 설계 결정 필요: 복무 중 NPC 경기 기록의 보존 범위/압축.

검증 상태: 서비스 2년 출발 재계약은 여전히 미검증(통과도 제품 실패도 아님). 독립리그 1·2년 출발은 통과(15737c6, d76f99d). slim 변경은 효과가 없어 되돌렸다.
다음 시도 후보: (a) 캐시 없이 메모리에서만 2년을 돌려 재계약 단계까지(수 시간) 확인, (b) 복무 중 NPC 경기 기록 보존 정책을 사용자와 결정 후 구조 변경.
