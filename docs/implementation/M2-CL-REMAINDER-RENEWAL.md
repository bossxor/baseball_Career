# M2-CL — 원구단 잔여 시즌 일할 재계약

사용자 확정1번의 원구단 수락 경로를 구현한다. 이 작업 시작 시 origin/main과 체크아웃은00316d0으로 일치했고 V: 추적1134파일도 바이트 단위로 모두 일치했다. 작업은 기존 체크아웃이며 V:/.git은 만들지 않는다.

## 구현 범위

마지막 동결 계약 지급일 뒤 진행이 멈추면 offerKboRemainderRenewal로 E30을 연다. 기존 비FA 연봉 산식을 재사용하고 날짜/가치/계약 원장/등록/예산 근거를 고정한다. 반복 조회와 제안 재호출은 재추첨이나 재가격을 하지 않는다. 명시 acceptKboRemainderRenewal이 원구단과의 현재 시즌 일할 계약을 활성화하고 저장된 다음 날짜부터 진행을 재개한다. 중도 은퇴는 기존 시즌 결산 조건을 유지한다.

새 계약은 ACTIVE_PRORATED 상태와 선택적 remainderPay를 쓴다. 원래 복무 계약과 지급 영수증은 previous에 그대로 남는다. 일반 계약/초기 세계는 재작성하지 않는다. 기존 복무 지급과 새 일할 지급은 공용 공식 경기/등록 증거 검사를 사용한다. 등록 벤치·부상 선수도 지급하며 포스트시즌·국가대표·상무 등록은 해당 원구단 급여를 생성하지 않는다.

실제 등록일 일급은 round(연환산 연봉/144), 시즌 마지막 정규 급여일은 실제 지급일수의 비례 총액과 차이를 정산한다. 양/음 반올림 차이는 돈만 조정하고 경기나 등록일을 추가하지 않는다. 포스트시즌에는 새 등록일 급여가 없다. 승격/강등으로 날짜가 달라질 수 있어 양 리그 남은 원구단 경기 날짜 합집합을 최대 예약으로 쓰고 매일 미사용분을 해제한다. 이미 지급한 이전 계약 금액도 같은 구단의 당해 급여 합계에 포함해 빠뜨리거나 두 번 더하지 않는다. 예산 부족은 복제된 명령 결과 안에서 거절하며 자동 재정 구제/무단 연장을 만들지 않는다.

시즌 끝의 일반 재계약·다음 연도 활성화에서는 일할 계약을 이월하지 않는다. servicePay 또는 remainderPay가 교체되면 contractHistory에 전체 계약/원장을 보존한다. 현재 계약의 개인 은퇴 정책을 바꾸지 않는다. E30 문구는 적용 기간을 확인하도록 일반화했으며 ID99개/선택지164개/증거 필드는 유지한다.

## 호환과 롤백

기존 저장은 선택 필드 없이 종전 계산을 유지한다. 신규 활성 일할 계약은 구형 reader가 ACTIVE만 허용하는 계약 검증에서 거절하도록 상태를 구분한다. 새 기간 계약·과거 원장을 구형 일반 연봉 계약으로 강제 축소하지 않는다. 실제 서비스의 혼합 버전 운영/DB 마이그레이션은 아직 없으며 롤백은 적용 전 스냅샷과 일치하는 코드의 동시 복원이다. 적용 후 실제 지급이 있으면 이를 보존한 새 코드에서 검토해야 한다.

## 검증과 한계

핵심 지급 및 기존 원장9/9, 새 일할 계약/전체 흐름5/5 집중 검증 통과 후 메타데이터 보존·문구를 보강했다. 최종 전체 npm run check496/496·실패0·취소0, lint/타입/build/골든/이벤트/설계10종 통과. duration_ms 941209.7101. [전체 로그](evidence/M2-CL-check.log). 흐름 검증은 이전/중간 날짜를 통제한 뒤 실제 마지막 지급일·수락 후 경기·마지막 정규 경기일·포스트시즌·다음 연도 명령을 실행한다. 전체18개월 모든 경기나 실제 앱/계정/DB를 검증했다고 하지 않는다.

거절 후 다른 구단 비교/보류 중 어떤 경로를 원하는지 사용자 결정은 다른 구단 제안 비교·계약 전 경기 보류로 확정됐다. 이번에는 원구단 수락 경로만 구현하며 시장 탐색·다른 구단 이적을 완료로 표시하지 않는다. ACTIVE/28세 전체 기한·복무 성장·NPC6월 복귀·실제 UI/계정/세이브/APK도 남아 있다. 전체 구현 추정35% 완료·65% 남음은 유지한다. 작은 M2 계약 경로로 영역50% 추정을 올리지 않았다.

최초 전체 검사는 제거 중 남아 있던 미사용 wrapper의 canonicalJson 참조로 타입 검사에서 중단됐다. 첫 문자열 수정이 적용되지 않은 재시도도 같은 오류로 중단됐다. wrapper를 실제 제거한 최종 소스로 전체 검사를 처음부터 다시 완료했다. 실패 로그도 보존한다.
