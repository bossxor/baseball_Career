# M2-CN — 현역 복무·계약 정지·등록 제외·복귀

## 연결 범위

S26의 kboActiveServicePreview는 계약·기한·복귀일을 읽기만 한다. confirmKboActiveService라는 별도 명시 명령으로 다음 시즌 입대를 확정한다. 계약 선택과 기존 차단 사건을 먼저 처리한다. 원구단 권리를 보존하고 상무 팀/대여 명단은 만들지 않는다.

SPORTS와 ACTIVE가 기존 두 블록 달력을 공유하며 원래 상무 프로그램/복귀 키는 그대로다. E51은 현역 첫 블록, E52는 상무 첫 블록, E53은 실제 복무 완료 뒤 원구단 복귀 확인이다. 첫 블록은 국내 정규 달력 종료, 둘째는6월30일 일마감 완료다.

현역은 원구단 보유 선수/계약 목록에 남되 실제 KBO/FUTURES 투영에서 모두 제외한다. 원구단은 기존 최소 편성 복구로 필요한 선수만 보충하고 정상28명/독립 퓨처스 명단을 갖춘다. 개막 명단·일정 공개 조회는 현역을 퓨처스 출장 선수처럼 표시하지 않는다. 내부 competitionKey의 FUTURES 기본 슬롯은 원구단 복귀용이며 실제 등록 근거는 경기 투영/건강 영수증이다.

경기 출장·등록일 지급·구종 경기 XP는0이다. 날짜 마감은 NONE 휴식 피로 감소만1회 수행하며 부상 잔여 팀경기를 날짜로 소모하지 않는다. 특별강화와 새 구종 학습은 막는다. 육성 계획/전략 설정은 원래대로 보존하지만 현역 기간 자연성장은0이다. 복귀 후 기간만 기존 PRO 성장 계산에 누적한다. 세계시즌 공통 예산·강화 키·노쇠 규칙은 유지한다.

연봉 자체를0으로 바꾸지 않는다. 남은 계약 경기일수/금액을 동결하고 복무 중 해당 원금 지급0·해당 연도 구단 예약을 계산한다. 현역은 상무 없는10팀과 상무 포함11팀 달력 가능성을 고려한 복귀 연도 예약 전망을 쓰며 실제 일정/등록일 마감에서 재계산한다. 실제6월30일에 계약 원장을 재개하고, 다음 날짜부터 원구단 등록일 지급을 재개한다. 이미 지급한 원금을 연수+1로 다시 만들지 않는다.

## 저장 호환

현역 확정 시 복제된 KboCareer의 schemaVersion을2로 올린다. 이때 현재 연도의 계약/돈/능력/기록은 재작성하지 않는다. 일반/상무/최초 생성의 기존v1 값은 유지한다. 모든 KBO 명령은 별도 assertKboCareerRevision으로v1/v2를 읽고, 학교/옛 코드의v1 guard는 그대로여서v2 진행을 거절한다. 개막·은퇴 공개 조회도v2를 지원한다. Save envelope/DB 스키마 전체 버전과 이 엔진 루트 버전을 혼동하지 않는다.

확정 직후 아직 servicePay가 없는 예약 저장도v2다. 그렇지 않으면 옛 코드가 새 현역 상태를 무시하고 다음 시즌에 선수를 출전시킬 수 있었다. 테스트는 변경하지 않은v1 revision guard가 현역v2를 거절함과 새 KBO 실제 진행/복귀/은퇴 경로를 확인한다. 배포된 혼합 버전 앱 전체를 시험한 결과는 아니다. 롤백은 확정 전 원본 저장과 코드의 동시 복원이며, 진행한v2를 숫자만1로 낮추지 않는다.
