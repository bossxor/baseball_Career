## 구현 범위

- DB에 기본값 JSONB인 `game_saves.state_format`과 `game_save_parts`를 추가했다. 기존 저장을 일괄 변환하지 않고, 기존 JSONB와 작은 상태를 그대로 읽는다. 새 명령에서 큰 상태가 된 경우만 PARTS_V1으로 기록한다. 별도 형식 열을 두어 기존 상태의 문자 그대로인 `$playballState` 키도 보존한다.
- codec은 객체·배열·값·문자열의 bounded event stream을 최대1MiB 조각으로 직렬화한다. 전체 커리어 JSON 문자열을 만들거나 합치지 않는다. 작은 평면 기록은 한 event로 유지하고, 긴 문자열·키는 별도 조각으로 처리한다. 단일 값 문자열 자체와 전체 엔진 객체의 메모리 한계까지 제거하는 기능은 아니다.
- 조각 번호·revision·각 조각 SHA-256·전체 저장 stream SHA-256을 검증한다. 누락·손상·중복 키·불완전 구조를 거부하며 특수 키는 prototype을 바꾸지 않고 복원한다.
- 명령은 기존 행 잠금·소유권·중복 영수증·revision 검사 뒤 상태를 읽는다. 조각 교체·상태·revision·영수증은 같은 트랜잭션에서 확정한다. reader는 FOR SHARE를 유지해 조회 중 다른 revision의 조각으로 바뀌지 않게 한다.
- 홈·Flow·화면·생성·복원·백업·내보내기·프로파일러와 테스트의 상태 검사 helper를 연결했다. 백업 파일 내용은 작은 envelope가 아니라 복원된 실제 상태다. 기존 백업 형식은 유지한다.
