# M2-CQ — 시즌 중 타 구단 잔여 계약 수락·이적

2026-10-23. M2-CP의 고정 제안을 실제 원자 수락으로 연결한다. 사용자 확정인 기존 선수 가치 연봉·남은 등록일 지급을 따른다. 새 연봉 수치나 추첨·트레이드 보상 규칙을 추가하지 않는다.

## 구현 범위

- `acceptKboRemainderTransfer`는 revision/E30 버전/제안 key·전체 비교 근거·현재 재무/정원을 검사하고 한 복제본에서 계약·소속·보유권·등록·이적 영수증과 진행 재개를 게시한다. 원제안과 경쟁 제안은 수락 불가가 되고, 실패는 원본·돈·기록·RNG를 바꾸지 않는다.
- 잔여 지급 v1은 같은 구단 값을 그대로 유지한다. 타 구단만 v2를 생성하고 이전 계약/복무/급여 영수증 snapshot을 보존한다. 새 계약 charge는 새 구단의 지급/예약만 포함하고, 세계 검증은 보존된 이전 지급을 원구단에 귀속한다. 새 재무 필드를 만들지 않아 보장/지원금 writer가 귀속 이력을 버리지 않는다.
- 새 팀은 FUTURES부터 등록한다(D, 1군 보장 없음의 기존 제안 계약). 대상 두 구단만 기존 건강 등록을 보존하며 부족한 자리만 복구한다. 기존 최소 충원 helper를 공유하고 원구단 1군 빈자리·독립 FUTURES 타순/투수·정원을 검증한다. 무관한 구단의 기용/계약은 재선정하지 않는다. 필수 충원만 기존 최저계약/예산 보호 정책을 사용한다.
- 성장·강화는 한 세계시즌 원장/사용 키를 유지한다. 이적 전에 기존 계획의 원래 날짜를 고정하고, 이적 이후 팀경기 수는 실제 건강 등록과 공식 경기를 결합한다. 새 구단의 입단 전 경기로48/72 창을 열지 않는다. 콜업20경기 구간도 새 등록일부터 시작하며 옛 검토/E09를 보존한다.
- 완료된 군 프로그램의 원구단/계약/성장 구간과 현역 복귀6경기 이력을 유지한다. 군 프로그램을 가짜로 만들거나 새 구단으로 다시 쓰지 않는다. 구종 book/XP/학습·부상·훈련·스타일·관계·공식 기록은 초기화하지 않는다.
- 새 팀 최초 동료1명/E94를 기존 helper로 형성한다. 시즌 중 관계 조회/읽음 처리는 현재 소유권/등록을 검증하고, PRE의 기존 봉인 검사도 유지한다. 계약 공개 조회는 실제 수락한 구단의 연봉/남은 날짜를 표시한다.

## 호환과 재시도

새 이적 저장은 KboCareer v4다. 기존 v1/v2/v3 저장과 같은 구단 잔여 계약 v1은 유지한다. 이전 상무 저장 중 군 건강 영수증 없이 공식 출장만 있고 성장 정책 버전이 없는 유형은 타 구단 수락을 게시 전에 원자 거절한다. 과거 정책을 임의 승격하지 않으며 원구단 수락 경로는 유지한다. 새 이력/급여 v2를 숫자만 낮춰 진행하려는 입력은 거절한다. 다음 연도·병역 writer도 v4를 낮추지 않는다. 이전 코드로 돌아가려면 최초 이적 전 전체 snapshot을 복원해야 하며 신규 영수증 일부만 삭제하는 롤백은 허용하지 않는다.

같은 원본 command의 결과는 결정론적이다. 이미 적용한 결과로 재실행하면 상태 검사로 거절한다. DB가 아직 없으므로 서버 저장 시 revision CAS/command receipt가 필요하며 현재 엔진만으로 네트워크 exactly-once를 구현했다고 표시하지 않는다.
