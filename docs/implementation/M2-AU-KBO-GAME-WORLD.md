# M2-AU — 프로 경기 엔진 투영과 중간 재개

2026-10-21. 프로1군/퓨처스 로스터를 기존 실제 경기 엔진·공식 기록/구종XP 작업자에 연결하는 내부 경계를 추가했다. 프로 커리어 날짜/건강 마감 명령은 아직 연결하지 않았다.

## 구조와 보존

기존 prepareSchoolCompetitionGame/commitSchoolCompetitionGame의 세계 인자를 필요한 필드만 가진 CompetitionGameWorld로 좁히고 commit 반환은 입력 W를 보존한다. 학교의 호출 인자/반환값·오류·정렬·RNG·직렬화 basisWorld는 그대로다. schools 필드는 기존 내부 팀 목록 이름이며 프로를 HighSchoolCareer로 단언하지 않는다. 이 타입 추출 전후 기존 경기5/5를 동일하게 통과했다.

createKboCompetitionGameWorld는 유효한 프로 등록/계약과1군28명의 고유 소속을 검사하고 전체501명 신원/구종·세계 seed를 복제한다. 경기 로스터는1군 명단과 그 보집합으로 투영한다. 각각280/221명이며 두 리그에 같은 선수 등록은 없다. 계약/재무/학교 archive/숨김 상태를 공개 API로 반환하는 DTO가 아니다. 내부 경기 작업자 입력이다.

선발·부상/휴식·최근 성적·특성·성향은 기존 context를 재사용한다. 이 함수가 자동으로 승격/치료하거나 선발 로테이션 규칙을 새로 정하지 않는다. 상위 커리어 명령이 phase/날짜/큐와 실제 기용 context를 먼저 인가해야 한다. 개막 확정 상태 전체를 계속 PRE로 두고 경기를 몰래 반영하지 않는다.

## 실제 경기 증거

- 관련10/10: 신규 프로1 + 기존 학교5 + 일정4. 실제 서명한 투수의1군/퓨처스 각각 실제1경기를 엔진 FINAL까지 진행하고 PA13에서 JSON 복원 후 PA7씩 진행한 결과와 연속 진행을 비교했다. 완전히 같은 경기/기록·구종 결과, 공식 KBO/FUTURES REGULAR 범위와1회 게시/중복 무효·날짜 위조 거절을 확인했다. 원래 커리어 루트는 변경하지 않는다.
- 별도 개막일 실측10경기(KBO5/퓨처스5)가 모두 완료됐다. 실제 모든20팀의 라인업/구종이 엔진에 들어가며 해당 리그 하루 중복 선수0이다. 원본은 고교216경기를 유지하고 반환된 worker 원장만226경기로 증가했다. 이것을 프로 커리어 진행 완료나 UI/DB 저장 증거로 보고하지 않는다. evidence/M2-AU-opening-day.log 참조.
- 첫 집중 테스트에서 변조1군 명단의 거절이 빠진 것을 발견했다. 모집 세계 검증은 firstTeam을 검사하지 않으므로 프로 경기 투영 경계에28명·고유성·소속 검사를 추가해 최종10/10을 통과했다.
- 타입/lint/전체 build·compiled 골든·이벤트 동기화·설계 정적10종·HTTP smoke 통과. 추가 전체 npm test는 사용자5% 체크포인트를 지키기 위해653.38초에 명시적으로 중단했다. Node는 완료356통과와 종료한 college-career.test.ts/high-school-progress.test.ts 두 파일을 fail2로 표시했다. 이2개는 게임 단언 실패를 확인한 것이 아니라 Stop-Process로 종료한 미완주이며 전체 통과를 주장하지 않는다. 다음 환경에서 전체 npm test를 다시 완주해야 한다. evidence/M2-AU-full-tests.log 및 M2-AU-full-test-status.json 참조.

## 다음 상위 명령의 필수 조건

1. PRE→정규 진행 phase 전환 후 개막/계획 영수증을 현재 피로/구종/기록과 재대조하지 않고 역사로 보존한다. 현재 PRE 전용 reader를 시즌 중에 직접 재사용하지 않는다.
2. 두 리그의 날짜순 큐에서 순차 준비/게시한다. 경기 반환 투영의 전체 repertoires를 무조건 덮어쓰면 다른 리그의 먼저 반영한 XP를 되돌릴 수 있다. 현재 세계를 다시 투영하거나 해당 job.pitchDevelopment에 실제 포함된 key만 병합해야 한다.
3. records·구종·건강·피로·실제출장·성장 기간/특성/관계 마감과 날짜/큐를 하나의 원자 커리어 결과로 반영한다. 일마감 전/후 중간저장·JSON 재개·같은날 두 리그 중복출장 거절을 검증한다.
4. 기존 closeSchoolCompetitionDay를 두 리그에 차례로 호출하면 두 번째가 같은날 health.games를 거절하거나, 우회 시 피로/회복을 두 번 반영할 수 있다. 프로 일마감은501명 전체 하루1회 피로/휴식을 적용하고, 각 경기의 해당 리그 등록 명단만 건강 팀경기로 정산해야 한다. 두 리그 결과를 단일 날짜 증거로 묶어 동일날1회와 양 리그 scope를 검증한다.
5. 실제 경기 context의 선발 로테이션·사용 가능 선수·최근 성적과20팀경기 재편성을 기존41/44 규칙에 맞춰 연결한다. 예제 context의 첫 SP 선택을 최종 프로 AI로 채택하지 않는다.

새 게임 수치/확률·패키지/설정/DB 스키마 변경은 없다. 기존 게임 세이브 형태/골든은 보존한다. 앱/UI·계정 동기화/Neon·APK는 미구현이다.
