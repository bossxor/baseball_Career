# M2 일괄 구현·통합 검증 계획

2026-10-28 사용자 지시 변경. 작은 단계마다 전체 npm run check를 반복하지 않는다. 남은 M2를 기능군으로 이어 구현하고, 전체 구현 묶음이 끝나면 전체 검사를 한 번 실행한다. 실패는 기능군별로 수정하고 영향 있는 검사만 재실행한다.

## 상태 표기

- 구현 중: 실행 코드 연결이 아직 끝나지 않았다.
- 구현 완료·검증 대기: 코드 연결은 끝났지만 통합 실행을 아직 확인하지 않았다.
- 검증 통과: 실제 실행 로그가 있다. 통제 fixture/실제 경기/기기 증거는 구분한다.

최신 검증 완료 기준은271900f(EL)이다. 이후 변경을 이 기준의 통과 수에 합치지 않는다. STATUS의60%는 이전 범위 추정이며 새 테스트 수를 진행률로 환산하지 않는다.

## 구현 작업판

| 기능군 | 상태 | 작업 |
|---|---|---|
| 반복 마이너 갱신·갱신 후 콜업 | 수정 진행·통합 검증 대기 | 계약 epoch/구단/예산 재생, legacy EL 저장 호환, E66 역사 receipt 바인딩. 기존 집중2개 통과 후 사용자가 검증 방식 변경. |
| 미국 E61 강등·권리 조회 | 구현 중 | 기존 반환 계약 보존, NAV와 실제 강등 명령 연결, 성공/재개/옵션/급여 보존 사례 작성 |
| 대표 부상 후보 고갈·긴급 등록 | 대기 | 최초 후보 고갈 때 실제 하위리그 후보를 재검사, 과거 명단/점수/출장/seed 보존 |
| 국내 복귀·세계/재무 원장 인계 | 미구현 | 실제 US 최신 선수와 같은 연도 KBO 세계를 연결할 소유권 계약부터 적용. 옛 sealedPlayer 복원 금지 |
| 공통 국제 날짜·US 후보/국적 | 확인 중 | 기존 구현과 잔여를 재분류하고 실제 필요한 연결만 구현 |
| 99사건·24경로·PF-D | 확인 중 | 미감사와 실제 미구현을 구분. 문자열/ACK/fixture로 완료 표기 금지 |

M6·구단/실기기 범위는 이 브랜치에 끌어오지 않는다. 수치/게임 정책이 실제 비어 있으면 질문하고 다른 구현을 계속한다.

## 중간 확인 원칙

전체 테스트는 보류한다. 타입/문법·정적 연결과 데이터 보존에 직접 관련된 짧은 확인만 필요할 때 수행한다. 테스트는 함께 작성하되 실행 대기 목록에 등록한다. 이미 실행한 결과는 그대로 보존한다. 검증 전 기능을 최종 완료로 보고하지 않는다.
