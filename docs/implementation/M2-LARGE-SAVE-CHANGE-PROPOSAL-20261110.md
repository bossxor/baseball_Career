# 대용량 저장 변경안 — 로컬 구현 승인

2026-11-10. 사용자가 “권장안으로 로컬 구현·검증 진행”을 승인했다. 로컬 구현 중이며 운영 DB에는 적용하지 않았다. [재현과 실험](M2-JSONB-BOUNDARY-20261110.md).

## 문제와 권장안

기록을 지우거나 경기 규칙을 바꾸지 않고, DB에 저장하는 상태를 크기가 제한된 조각으로 분리한다. 엔진과 화면이 받는 SaveState 형태는 유지한다. DB를 다른 서비스로 옮기거나 메모리만 늘리는 안은 실제 PostgreSQL의 JSONB 컨테이너 한도를 해결하지 못하므로 채택하지 않는다.

실제 다음 상태221,115,560바이트의 임시 저장 실험에서 단일 JSONB는54000으로 실패했고211개 조각은 원본 해시·롤백·기존 저장 보존을 통과했다. 그러나 단순 문자열 분할 실험을 제품 구현으로 채택하지 않는다. 제품 경계는 전체 JSON.stringify/join 없이 객체·배열 구조를 조각별로 인코딩·복원해야 한다.

## 변경 범위

| 위치 | 필요한 변경 |
|---|---|
| packages/db/src/schema.ts 및 실제 SQL 마이그레이션 | game_saves의 저장 형식 표시, 저장ID·revision·조각번호와 내용·검증 해시를 갖는 조각 테이블, 삭제 연쇄·조회 인덱스 |
| 공통 상태 읽기·쓰기 경계 | 기존 JSONB 읽기 유지, 새로운 bounded 구조 인코딩·디코딩, 손상·누락·중복 조각 거부 |
| apps/api/src/commands.ts | 기존 행 잠금→소유권→영수증→revision 순서 유지, 상태·revision·영수증을 한 트랜잭션에서 확정 |
| apps/api/src/career-views.ts | 소유권 확인 뒤 같은 revision의 상태 복원, 여러 쿼리의 스냅샷 불일치 방지 |
| apps/api/src/game-creations.ts·restores.ts | 생성·복원과 재전송에 공통 쓰기 경계 적용, 복원 대상 검증 유지 |
| apps/api/src/private-files.ts | 백업·내보내기 reader와 무결성 경계 적용, 큰 JSON 문자열 제한을 숨기지 않음 |
| 테스트·fixture·프로파일러 | 직접 state 열을 읽는 경로를 새 경계로 전환, 원본 source manifest 유지 |

작은 기존 저장은 전환 전까지 그대로 읽는다. 새 명령의 정상 커밋에서만 상태 형식을 전환하고, 실패하면 기존 JSONB와 revision·영수증이 함께 유지된다. 조각 읽기 실패 시 빈 상태를 반환하거나 경기를 재시뮬레이션하지 않는다. 해시는 원본의 논리적 상태와 비교하고 게임·선수·시드·원장·봉인을 삭제하거나 재생성하지 않는다.

## 승인 후 구현·검증 순서

1. bounded 구조 codec과 호환 reader, 스키마를 구현한다. 빈 객체/배열·한글·서러게이트·특수 키·수치와 손상 조각의 회귀를 확인한다.
2. 명령·조회·생성·복원·백업 호출자를 함께 연결한다. 각 쓰기 단계 실패, 중복 commandId, stale revision, 동시 명령, 다른 사용자 접근의 회귀를 묶어서 수행한다.
3. 보존한 실제 실패 직전 상태로 다음 API 명령을 실행하고 원본·기록 해시를 비교한다. 이후 실제 시즌 완주와 귀국 HTTP 실패 건을 재실행한다.
4. 집중 검증 통과 뒤 전체 check를1회 실행한다. 제품 DB의 마이그레이션이나 배포는 이 로컬 구현 승인과 구분한다.

## 수용 기준과 한계

- 기존 저장을 읽고 실패 없이 재개하며 명령1개당 revision·영수증이 정확히1회 확정된다.
- 저장·재조회한 논리적 상태와 공식 기록의 해시가 동일하다. 조각 손상은 검증 오류로 거부한다.
- 실제 미국 시즌 및 귀국 HTTP를 통과하기 전에는 M2 완료나 대용량 저장 해결을 선언하지 않는다.
- DB 저장을 분리해도 엔진은 전체 객체를 메모리에 올린다. 장기 커리어 메모리는 실제 측정 대상이다. 백업·복원의 전체 문자열/버퍼 한계도 별도 점검하며 저장 조각 실험만으로 해결했다고 주장하지 않는다.

## 승인 경계

사용자가 전달한 TF 운영 요청 §1-2의 “기존 시스템의 주요 아키텍처를 근본적으로 변경하는 경우”에 해당하므로 제품 저장 구조 적용 전에 승인을 받는다. 승인 대상은 위 호환 저장 경계의 로컬 구현·검증이다. 운영 DB 변경이나 배포는 포함하지 않는다.
