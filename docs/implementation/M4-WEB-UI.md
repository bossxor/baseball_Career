# M4 — 웹 UI 핵심 화면 (진행 기록)

2026-10-26. M2(엔진)·M3(DB/인증/저장 API)는 다른 환경에서 진행 중이라 겹치지 않는 `apps/web`만 구현한다. 웹 번들은 엔진·API·DB 패키지를 직접 가져오지 않는다(린트 강제). 서버가 채울 읽기 모델은 `apps/web/src/model.ts`의 자체 DTO이고, `@playball/rules`(능력·유형·이름 규칙)만 공유한다.

## 핵심 12개 화면(구현 기본값 D — 설계는 개수만 12로 정함)

홈 S01 · 생성 S02 · 커리어 S03 · 고교결산 S04 · 드래프트 S05 · 사건 S06 · 결산 S07 · 계약 S08 · 은퇴 S09 · 스타일 S22 · 강화 S23 · 졸업진로 S28. 선정 기준은 120의 M4 범위(홈·생성·시즌 진행·결과) 한 판을 끝까지 돌 수 있는 최소 집합이다. 상태 문구 12종은 `docs/design/screen-state-catalog.json`과 같고 테스트가 일치를 검사한다.

## 구현됨 (이번 단위)

- **뼈대**: `ScreenFrame`(상단바/뒤로/저장 상태→제목→상태 배너→본문, `aria-busy`·`role=alert/status`), `Button`, `FieldError`, 해시 라우터(`#/`, `#/create`, `#/career/:id`)와 알 수 없는 주소의 홈 대체, `PlayballApi` 인터페이스(M3가 구현할 경계)와 메모리 `fixtureApi`(같은 `commandId` 재시도는 같은 저장·같은 진행 — CR01 성질).
- **S01 홈**: 최근 세이브 없음 문구, 이어하기(로딩 중 문구 유지·비활성·`aria-busy`, 내부 상태 문구는 노출하지 않음), 다른 게임 선택, 새 커리어. 구단·설정 버튼은 핸들러가 있을 때만 나타난다(없는 모드를 죽은 버튼으로 두지 않음).
- **S02 생성**: 01의 순서(이름→타자/투수→포지션→투타→유형→집중4→확인) 7단계. 이름은 NFC·공백 제거·1~12 글자소·제어문자 불가(규칙 패키지 `normalizePlayerName`). 좌투는 포수·2·3루·유격수 불가, 투수는 투구폼 필수, 집중은 서로 다른 4개이며 5번째 선택은 비활성/거절. 종류를 바꾸면 의존 선택을 초기화. 단계마다 오류는 입력 옆(`aria-describedby`+`role=alert`). 선택이 끝나면 유형 시작 능력·종합(`overall`) 미리보기. 키보드 Enter로 다음 단계.
- **S03 커리어**: 버튼은 서버가 준 `nextActions`만, 진행 단위 기본 "다음 주요 사건까지"(1경기·1주일 대안), 대기 사건이 있으면 진행 단위 잠금과 사건 행동만 노출, 비활성 사유 연결, 최근 기록 없음 문구.
- **디자인**(ui-ux-pro-max 점검표 적용): 남색/녹색 기존 브랜드 유지, 본문 16px·행간 1.55, 터치 대상 44~48px, 포커스 링 3px, 오류 색 대비 4.5:1 이상, `prefers-reduced-motion` 존중, 모바일 1열·768px 2열·최대 1200px, 아이콘 이모지 없음.
