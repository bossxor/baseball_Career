# Android 기본 플레이와 선택 연동

2026-11-24 사용자 결정. 앱을 처음 열면 바로 게임 홈을 보여준다. 새 게임과 이어하기는 로그인 없이 동작한다. 계정 로그인은 사용자가 기기 간 저장 연동을 선택했을 때만 연다.

## 저장과 화면

- 기기 저장은 해당 설치가 소유한다. 앱을 껐다 켰을 때 마지막으로 확정된 경기와 선택을 불러온다.
- 계정 저장은 기존 서버 명령·권한·저장 리비전을 사용한다. 로컬과 계정 세이브가 함께 있을 때 계정 연결만으로 기존 데이터를 이동하거나 덮어쓰지 않는다.
- 기존 웹 계정 세이브의 진입과 권한은 유지한다. Android 구현이 확인되기 전까지 이번 결정을 웹 기본값으로 확대하지 않는다.

## 구현 순서

1. 실제 경기 엔진을 Android WebView에서 실행하고 영구 저장에 쓸 수 있는지 확인한다. 서버 없이 공식 경기 기록을 만들고 앱 프로세스 종료 뒤 같은 저장을 복원하면 통과다.
2. 서버 권한 검사와 전송 코드를 게임 명령·화면 변환과 분리한다. 기기 실행기는 기존 명령·화면과 동일한 타입을 사용한다. 게임 결과·리비전·재실행 방지 영수증을 같은 저장 트랜잭션에서 확정한다. 긴 시즌 계산은 화면 이벤트와 분리하고, 확정 청크마다 저장한다.
3. Android 홈과 새 게임·이어하기에 실제 기기 실행기를 연결한다. 기존 테스트 fixture 대신 공식 기록을 사용한다. 앱 강제 종료, 오프라인 재실행, 필수 선택 앞에서 정지하는 경우를 검증한다.
4. 별도의 계정 연동 진입점을 연결한다. 기존 계정 세이브를 읽고, 기기 세이브 이동과 충돌 처리의 상세 정책이 확정된 후 데이터 이전을 구현한다.

## 실기기에서 확인한 범위

1단계 통과. 별도 Capacitor APK의 내장 WebView에서 실제 고교 엔진을 실행해 2경기를 기록했다. 계정과 백엔드 없이 IndexedDB에 저장했고, 앱 강제 종료 뒤 새 프로세스에서 2경기와 리비전 4를 복원했다. [검증 결과](evidence/M2-20261124-android-local-proof.log)

## 앱 연결

Android 홈·새 게임·이어하기에 기기 실행기를 연결했다. 경기 엔진은 Web Worker에서 돌아가고, 저장 상태는 분할 인코딩한 뒤 IndexedDB에 리비전과 명령 영수증을 함께 쓴다. 저장이 확정되어야 다음 화면을 표시한다. 로컬 경로에서도 서버와 같은 초기화·명령·화면 데이터 생성기를 쓴다.

API 주소를 설정한 APK에서는 홈의 ‘계정 저장 열기’로 로그인 화면을 연다. ‘이 기기 게임으로’는 기존 기기 저장으로 돌아간다. 계정에 보관된 게임과 기기 게임은 각각의 목록에서 열며, 기기 저장 업로드·다운로드와 충돌 선택은 남았다. 로컬 시즌은 앱이 종료되면 마지막으로 확정한 진행 단위에서 이어한다.
