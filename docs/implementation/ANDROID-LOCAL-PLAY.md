# Android 기본 플레이와 선택 연동

2026-11-24 사용자 결정. 앱을 처음 열면 바로 게임 홈을 보여준다. 새 게임과 이어하기는 로그인 없이 동작한다. 계정 로그인은 사용자가 기기 간 저장 연동을 선택했을 때만 연다.

## 저장과 화면

- 기기 저장은 해당 설치가 소유한다. 앱을 껐다 켰을 때 마지막으로 확정된 경기와 선택을 불러온다.
- 계정 저장은 기존 서버 명령·권한·저장 리비전을 사용한다. 로컬과 계정 세이브가 함께 있을 때 계정 연결만으로 기존 데이터를 이동하거나 덮어쓰지 않는다.
- 기존 웹 계정 세이브의 진입과 권한은 유지한다. Android 구현이 확인되기 전까지 이번 결정을 웹 기본값으로 확대하지 않는다.

## 구현 순서

1. 실제 경기 엔진을 Android WebView에서 실행하고 영구 저장에 쓸 수 있는지 확인한다. 서버 없이 공식 경기 기록을 만들고 앱 프로세스 종료 뒤 같은 저장을 복원하면 통과다.
2. 서버 권한 검사와 전송 코드를 게임 명령·화면 변환과 분리한다. 기기 실행기는 기존 명령·화면과 동일한 타입을 사용한다. 게임 결과·리비전·재실행 방지 영수증을 같은 저장 트랜잭션에서 확정한다. 긴 시즌 계산은 화면 이벤트와 분리하고, 확정 청크마다 저장한다.
3. Android 홈과 새 게임·이어하기에 실제 기기 실행기를 연결한다. 기존 테스트 fixture 대신 공식 기록을 사용한다. 앱 강제 종료, 오프라인 재실행, 필수 선택 앞에서 정지하는 경우를 검증한다.
4. 별도의 계정 연동 진입점을 연결한다. 기존 계정 세이브를 읽고, 기기 세이브 이동과 충돌 처리의 상세 정책이 확정된 후 데이터 이전을 구현한다.

## 실기기에서 확인한 범위

1단계 통과. 별도 Capacitor APK의 내장 WebView에서 실제 고교 엔진을 실행해 2경기를 기록했다. 계정과 백엔드 없이 IndexedDB에 저장했고, 앱 강제 종료 뒤 새 프로세스에서 2경기와 리비전 4를 복원했다. [검증 결과](evidence/M2-20261124-android-local-proof.log)

## 앱 연결

Android 홈·새 게임·이어하기에 기기 실행기를 연결했다. 경기 엔진은 Web Worker에서 돌아가고, 저장 상태는 분할 인코딩한 뒤 IndexedDB에 리비전과 명령 영수증을 함께 쓴다. 저장이 확정되어야 다음 화면을 표시한다. 로컬 경로에서도 서버와 같은 초기화·명령·화면 데이터 생성기를 쓴다.

API 주소를 설정한 APK에서는 홈의 ‘계정 저장 열기’로 로그인 화면을 연다. ‘이 기기 게임으로’는 기존 기기 저장으로 돌아간다. 계정 저장의 ‘이 기기로 복사’는 선택한 서버 리비전을 새 기기 슬롯으로 가져온다. 같은 리비전을 다시 복사하면 기존 사본을 유지한다. 로컬 시즌은 앱이 종료되면 마지막으로 확정한 진행 단위에서 이어한다.

계정 복사는 소유권을 확인한 뒤 분할 스트림으로 내려받으며, 전체 검증과 기기 저장이 끝난 뒤에만 새 항목을 표시한다. 기기 저장은 계정 홈의 ‘기기 저장 백업’에서 보관한다. 다른 기기의 같은 계정에서 ‘이 기기로 복원’을 누르면 별도 기기 저장이 생긴다. 같은 리비전의 반복 업로드는 백업 한 개로 처리하고, 같은 백업의 반복 복원은 이미 복원한 슬롯의 진행을 보존한다.

## 계정 백업 저장과 운영 반영

백업 하나의 전송 한도는 128 MiB다. 전체 조각이 검증·저장된 백업만 목록에 나온다. 백업은 소유 계정만 읽을 수 있고 서버 게임과 별도 테이블에 보관한다. 양쪽에서 진행한 저장의 자동 병합은 아직 지원하지 않는다.

운영 API를 갱신하기 전에 대상 DB에 [백업 테이블 마이그레이션](../../packages/db/drizzle/0003_device_backups.sql)을 적용한다. 로컬에서 기존 세이브를 유지한 채 스키마를 올렸고, Neon 개발 브랜치 `m3-dev`에서 마이그레이션 재적용과 백업 업로드·복원을 확인했다. 운영 DB 적용 뒤에는 운영 API를 배포하고, 앱을 실제 인증으로 연결해 백업과 복원을 한 번 확인한다. [Neon 검증 결과](evidence/M2-20261124-neon-device-backups.log)

## 앱 화면 실기기 검증

2026-11-24, SM-S948N의 별도 테스트 APK에서 최초 실행 → 로그인 없는 홈 → 선수 생성 → 고교 경기 → 강제 종료 → 다시 실행 → ‘이어하기’를 통과했다. 종료 전후 공식 팀 경기 수는 1로 같았다. 필수 집중 육성 선택을 열어 둔 세이브와 새 KIA 구단도 각각 강제 종료 후 같은 대상으로 열렸다. [실행 결과](evidence/M2-20261124-android-device-resume.log)

11월 24일 계정 백업 검증에서 Chromium 새 프로필로 원본의 1경기를 복원했다. SM-S948N에서도 원본 1경기와 복원본 2경기를 각각 확인했다. 같은 백업으로 다시 복원해도 2경기가 유지됐고 공식 계정 저장에도 변화가 없었다. [실행 결과](evidence/M2-20261124-android-device-backups.log)
