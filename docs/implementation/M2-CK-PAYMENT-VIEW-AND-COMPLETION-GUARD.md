# M2-CK — 병역 계약 조회·은퇴 잔여 일수·진행 중단 정합

2026-10-22. 07d84d6 다음 검수 보강. 새 게임 규칙이나 계약 자동 연장은 추가하지 않았다.

## 변경

kboServiceContractView는 복무 계약의 상태, 정확한 잔여 지급 경기일수, 지급한 경기일수, 미지급 원금, 해당 시즌 지급/예약액, 복귀 날짜만 공개한다. 원래 계약키·프로그램·영수증·RNG·잠재력은 내보내지 않는다. 커리어 입단/시즌 개시 조회에 선택적 payment로 연결했다. 일반 계약의 기존 조회 형태는 유지한다.

복무 중 은퇴할 때 달력상 한 시즌을 더 뺀 remainingContractYears를 만들던 문제를 수정했다. 새로운 복무 계약 은퇴 기록은 정확한 remainingPaidGameDays를 보존하며 연수 표시는 올림한 보조값이다. 예를 들어 미이행576일이 남아 있으면576일/4년으로 기록하고3년으로 깎지 않는다. 보관 조회도 원장과 대조한다. 개인 계약 종료라는 기존 은퇴 정책은 그대로이며 남은 일수를 계속 지급한다는 의미가 아니다.

마지막 지급 후 maxDays7 작업자가 다음 경기까지 들어가 CONTRACT_DECISION_REQUIRED를 던지던 경계도 재현했다. 이제 마지막 지급일 전체를 마감하고 CONTRACT_DECISION_REQUIRED stopReason으로 반환한다. 이후 호출은 새 날짜/경기 준비 전에 거절하므로 진행 단위가 커도 마지막 지급일이 취소되거나 다음 경기 기록이 먼저 생기지 않는다. 원래 마지막 정규 경기일에서 끝나는 계약은 시즌 결산·기존 E30 경로를 그대로 따른다. 같은 날 AI20경기 검토는 중단 전에 처리한다.

## 호환·남은 일

새 은퇴 메타데이터는 선택 필드이며 기존 저장과 일반 계약 DTO는 재작성하지 않는다. 새4년/576일 은퇴 레코드는 옛 reader가 이해하지 못할 수 있으므로 롤백은 적용 전 스냅샷과 같은 코드 버전을 함께 복원한다. 원장 지급분을 삭제하거나 새 메타데이터만 버려 과거 상태로 가장하지 않는다. 실제 DB/계정 배포 마이그레이션은 아니다.

사용자는 시즌 중 잔여 계약 소진 시 재계약을 선택하고 남은 시즌만 일할 계약하는1번을 확정했다. 자동 연장은 하지 않는다. 현재는 마지막 지급일 정상 마감/중단까지 구현됐고, 실제 제안·승인·일할 계약 지급·재개 명령 연결은 후속이다. 전체 검증 완료 뒤14 U·21에 결정을 기록했다. ACTIVE·28세 전체 기한·병역 성장 계수·실제 화면/저장도 남아 있다. 전체 구현 추정35% 완료·65% 남음은 유지한다. 작은 계약 정합 보강으로 M2 영역50%를 올리지 않았다.

전체 검사 뒤 런타임/테스트 해시는 그대로 확인했다. 진행 문서 갱신과 사용자1번 결정 기록 후 설계 패키지를 재생성하고 정적10종·MANIFEST359개를 다시 검증했다. [후속 검증](evidence/M2-CK-post-docs-design.log)·[해시 구분](evidence/M2-CK-post-docs-source.json).
