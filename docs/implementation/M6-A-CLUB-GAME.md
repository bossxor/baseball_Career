# M6-A — 독립 구단 새 게임의 뿌리와 시즌 진행 (엔진)

2026-10-26. M6(구단 모드)의 첫 단위. 이 환경은 M5·M7·M8을 다른 환경이 맡는 동안 M6만 `m6/club-mode` 브랜치의 별도 작업 폴더(git worktree)에서 구현했다. 공유 체크아웃의 미커밋 변경과 섞이지 않게 하기 위해서다. 새 게임 수치·확률은 추가하지 않았고 05의 규칙을 그대로 옮겼다.

## 구현됨

- **`createKboClubGame`**(kbo-club-game.ts): 구단·시작 연도(기본 2027)·난이도·seed로 전체 리그(10구단·가상 500명·계약·예산)를 한 번에 생성하고 내 구단을 지정한다. 어느 구단을 골라도 세계는 같고(구단별 유리한 분포 없음, 재추첨 없음) 생성 키는 입력에서 결정된다. 주인공이 없는 뿌리이며 보관 선수 투입(내 선수 사용 ON)은 아직 없다.
- **읽기**: `kboClubHome`(S13: 순위 10팀·내 예산 총액/지급/예약/보장/가용·다음 경기·차단 할 일), `kboClubRoster`(S14: 1군→2군 순, 포지션·나이·종합·부상·피로·계약), `kboClubRosterIssues`(35~60명, 1군 28명, 투수 10~15, 포수 2, 수비 8포지션, 1군 부상).
- **라인업**(S15): `autoClubLineup`(41/44 자동 선택기+건강한 선발 순환), `validateClubLineup`(중복·1군 밖·부상·좌투 포수/2·3루/유격수 불가·타순 불일치·선발 투수), `fitMultiplier`(적합도 0~100 → 수비 배율 .5~1.0 표시용). 손으로 만든 라인업을 실제 경기에 적용하는 연결은 아직 없다(경기는 자동 편성).
- **시즌 진행**(kbo-club-progress.ts): `startKboClubSeason`(로스터 문제가 있으면 `CLUB_ROSTER_INVALID`)과 `advanceKboClubGame`. 날짜마다 KBO→퓨처스의 전 구단 경기를 안전 청크(1000타석/20이닝)로 진행하고 JSON으로 재개하며, 날짜당 한 번 모든 선수의 피로와 팀경기 건강을 정산한다. 내 구단 선수의 부상/회복이 생기면 `HEALTH_CHANGE`로 멈추고 시즌 끝에 `SEASON_REVIEW`로 넘어간다. 구종 숙련은 경기에 쓰인 투수 것만 병합한다.
- 공유 코드 변경은 한 줄: `createKboCompetitionGameWorld`가 빈 주인공 키(`''`)를 구단 모드로 받아 주인공 검사를 건너뛴다(기존 호출은 그대로).
